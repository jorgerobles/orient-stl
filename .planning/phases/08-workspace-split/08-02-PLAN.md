Create 4 JS workers (one per WASM module). Each worker:
1. Lazy-loads its WASM binary via `import('../pkg/{module}_bg.wasm')` + `init()`
2. Listens for `onmessage` with typed input
3. Calls the WASM function
4. Posts the result back

**stl-parse.worker.ts**: Receives `{ type: 'parse', bytes: Uint8Array }`, calls `parse_stl_bytes(bytes)`, posts `{ type: 'result', positions: Float32Array }`.

**stl-repair.worker.ts**: Receives `{ type: 'repair', positions: Float32Array, weldEpsilon: number, maxHoleEdges: number }`, calls `repair_mesh_wasm(positions, weldEpsilon, maxHoleEdges)`, posts `{ type: 'result', positions: Float32Array }`.

**mesher.worker.ts**: Receives `{ type: 'mesh', positions: Float32Array }`, calls `precompute_mesh_data_wasm(positions)`, posts `{ type: 'result', positions, normals, areas }` as Float32Arrays.

**orient.worker.ts**: Rewrite existing `web/src/orient.worker.ts`. Receives `{ type: 'score', data: { positions, normals, areas, directions }, config, weights, ranker, maxCandidates, minAngleDeg, normLo, normHi }`. Calls `score_all_directions` → `rank_candidates` → `select_diverse` internally (same as current). Posts `{ type: 'results', candidates: Candidate[] }`.

Each worker uses the same error pattern: catch → `{ type: 'error', message: string }`.

Use typed message interfaces — define `WorkerRequest` / `WorkerResponse` discriminated unions per worker. Do NOT use `any`.

**IMPORTANT**: The WASM binary paths change from `../pkg/orient_core.js` to `../pkg/{module}_js.js` (wasm-pack output naming convention). Verify actual filenames after 08-01 builds.

**pipeline.ts**: Create the Unix-pipe orchestrator. Key design:
- Imports all 4 workers via Vite's `?worker` import
- Exports `runPipeline(file, config, onProgress)` that chains: parse → repair (optional) → mesh → orient
- Each stage runs in its own worker, data flows as Float32Arrays
- Progress callback receives `(stage: string, pct: number)` for UI updates
- Returns `PipelineResult { positions, normals, areas, candidates }`

```typescript
export interface PipelineConfig {
  autoRepair: boolean;
  orient: { criticalAngleDeg: number; refineIterations: number; excludeUnstable: boolean; mode: string; dedupeAngleDeg: number };
  weights: number[];
  ranker: string;
  maxCandidates: number;
  minAngleDeg: number;
  normLo?: number[];
  normHi?: number[];
}

export interface PipelineResult {
  positions: Float32Array;
  normals: Float32Array;
  areas: Float32Array;
  candidates: Candidate[];
}
```

Helper `runWorker<T>(worker, message, transfer?)` wraps postMessage/onmessage in a Promise.

**loadSTL.ts**: Simplify to:
- Remove all direct WASM imports (stl_parse_to_positions, repair_mesh_tris, etc.)
- `loadWithProgress` now delegates to `runPipeline` from pipeline.ts
- Keep `initWasm()` but it only initializes the orient WASM (for worker compatibility) or can be removed if workers self-initialize
- Keep `loadSTLBytes` and `prepareData` (for backward compat if needed)

Update `build:wasm` in package.json to run `make wasm`.
